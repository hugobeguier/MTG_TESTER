# Schema / validator / renderer changelog (consolidated pass)

Tests: `src/kernel/consolidated.test.ts`. Everything new is reported as a `needs` entry by `capabilities.ts` (nothing new looks implemented).

## Schema additions (schema.ts)
**Events / phases / refs**
- EventName: `dealt_damage` ("is dealt damage"), `commit_crime`.
- Phases: `precombat_main`, `postcombat_main` ("your first main phase").
- ObjRef: `sacrificed` (object sacrificed as a cost), `created` (token made by the previous step, living weapon), `iterated` (current object of a `repeat_for_each`; replaces the old `event_object` convention in loops).
- Duration: `until_end_of_your_next_turn`, `until_your_next_end_step`.

**ObjectFilter**: `notSubtypes`, `without` (keyword negation), `isCommander`, `sameName` (group: all share a name), `sharesCreatureTypeWith` (ObjRef), `chosenType`, `chosenColor`, `attackingYou`, `controller: "defending_player"`.

**Quantity**: `life_total {who}`, `starting_life`, `count_this_turn {event, filter?, actor?}` ("creatures that died this turn"), `players_count {who, where}`, math ops `div_down` / `div_up`.

**Predicate**: `compare {left: Quantity, cmp}` (total power etc.), `turn_number {scope, cmp}`, `chosen_is {kind, value}`, `step_done {step}` ("if you do"), `most_life {who}`, `attacked_defender {defender, who: all|none|any}`.

**Chosen option**: `choose` step gains `choice` (color, creature_type, mode, ...), `options`, `remember: true`. Read back by `filter.chosenType/chosenColor`, `ManaSpec.chosenColor`, static `addChosenType`, predicate `chosen_is`.

**Steps**: new kinds `fight {a,b}`, `investigate {amount?}`, `proliferate`, `extra_combat`. Typed fields: `source`, `excessTo`, `divided`, `alsoWho`, `excludeWho`, `position`, `order`, `faceDown`, `amountLockedOn: "cast"`, `reflexive` (targets chosen when the "when you do" trigger happens).

**Triggers**: `alsoOn: [{event, subject?, step?, whose?, fromZone?, toZone?}]` (multi-event: "enters or attacks", "attacks or blocks", "enters or is put into a graveyard"), `minCount` (attacks with N or more), `defender` (you / you_or_your_planeswalkers / other_player), `chapters` (Saga chapter numbers).

**Costs**: cost atom `loyalty` (+N / -N / -X as `-1 * X`); `costReduction.amount` is a Quantity, `per` optional, new `condition`; `costMod.delta` is a Quantity (it is ADDED to the cost, so a reduction is negative or `-1 * Quantity`).

**Cast options**: kinds `gift`, `escalate`; `optional` is now boolean (false = mandatory additional cost); `condition`; `perExtraMode`; `gift`.

**Statics**: modifiers `blockTax`, `setColors`, `extraLandDrops`, `addChosenType`; `attackTax.protects`.

**Mana**: `restriction` / `abilitiesOf` (spend restrictions) on colors/anyColor/perCount; `chosenColor`; `conditional {if, then, else}`.

**Other**: `ReplacementSpec.recipient / damageType / damageSource / duration`; `TargetSpec.perOpponent`; `Modes.repeatRestriction: "this_turn"`; `scripted.params`; `review.oracleOverride {text, source, typeLine?}`.

## Validator (validator.ts, scripts/validate-kernel-drafts.ts)
- Number words up to twenty, thirty..fifty, hundred; "half"/"twice" count as 2; ordinals (second..tenth) may account for a JSON number but never demand one.
- `review.ignore` can suppress `LITERAL_MISMATCH`: lexeme `literal` (all) or `literal:<n>` / `literal:{X}`.
- A PURE scripted stub (scripted marker, no steps/modes/static/replacement/mana/keyword param) is exempt from the literal check for its own text; put numbers in `scripted.params` when a marker should carry them. `handler` strings are never scanned for mana symbols.
- Ability words ("Ferocious -") no longer demand a second condition when the clause already says if/unless/as long as.
- "another/other": not flagged for "its other types", "another player", "each other opponent", "this creature or another X".
- "each": not flagged for "power and toughness each equal", "both power and toughness", "each of up to N targets", "all abilities"; backed by perOpponent / alsoWho / alsoOn / static affects filters / replacement subject filters.
- Gift / Escalate cast words; `{X}` satisfied by a variable `costReduction.amount`.
- "+1/+1 for each X" needs no literal 1; counter kinds like `"+1/+1"` carry their numbers.
- `STRUCT_CHOSEN_UNDEFINED` is card-wide (choice may live in another ability), covers `chosenType/chosenColor/chosen_is`; new `STRUCT_STEP_REF` for `step_done`.
- Static abilities may consist of a `costReduction` alone.
- Script: `review.oracleOverride` replaces `NO_ORACLE` (a warning `ORACLE_OVERRIDE` records the source); `--prune` (with `--write`) drops `review.ignore` entries no longer needed.
- Duplicated "enters or attacks" abilities are gone (`alsoOn`), so literals are no longer double counted.

## Renderer (prompts.ts)
- Opponent filters read "an opponent controls" (was "you don't control"); `defending_player` reads "the defending player controls".
- The card's own name replaces "this permanent" (`withCardName`, `setRenderCardName`; generic wording outside a card).
- Plurals: last word only, irregulars (Elves, Wolves, Fish, mice, ...); number words to twenty.
- addTypes renders lower case ("an artifact creature"); new descriptions for every field above; `describeManaSpec`; mana abilities now show in the approval render.

## Modes pass (generic modal spells) and pairing pass
- `modes.repeatable` (optional boolean): "You may choose the same mode more than once" (e.g. "Choose three. You may choose the same mode more than once."). Then `distinct` must be false. `modes.choose` was already min/max; the validator now parses every phrasing: "choose one" (1..1), "one or both" (1..2), "one or more" (1..options), "choose two/three/four/five", "choose up to N" (0..N), "any number" (0..options).
- Validator: `MODE_MISMATCH` compares oracle vs `choose` min/max and `repeatable`; a phrase only counts as a modal header when followed by a dash, period, comma or "that ..." ("Choose two target creature cards in your graveyard" is no longer read as modes, which fixed the Victimize false positive; "one or both" used to be read as exactly 1, which failed Saheeli's Artistry). The `may` lexeme is backed by `repeatable: true`.
- Renderer/prompts: "Choose one or both modes.", "Choose three modes. You may choose the same mode more than once."; approval render marks repeatable modes.
- Capabilities: new needs `modes:repeatable`, `modes:multiple` (choose.max > 1).
- New step kind `fight_pairs` (`fighters: "created"` = ALL tokens the previous create_tokens step made, `against: ObjectFilter` = pool, `pairing: "controller_chooses"`): each fighter fights a different object of the pool, pairing chosen by the controller, surplus fighters fight nothing. It is a decision step, so it gets a prompt ("Choose which creature each token fights..."), and a need `step:fight_pairs`. The "each" lexeme is backed by `fight_pairs`.
- Drafts: Mazemind Tome gates its life gain with `step_done` on the exile step; Ezuri's Predation uses create_tokens (count = creatures) then `fight_pairs`.

## Engine step (src/kernel/engine)
- No schema or capabilities.ts changes. The engine keeps its own support registry (`engine/support.ts`, derived from the step handlers in `engine/steps.ts`) because it runs more than the legacy `capabilities.ts` reports (modes, X, cast_during, counters as costs, scry...). `needs` in the card JSON still describes the LEGACY engine; the kernel engine's missing capabilities come from `cardUnsupported()`.
- Interpretation notes: `cast_during: main` = a main phase of the caster's own turn (Addendum reads "your main phase"); `distinct: false` modes are treated as repeatable; a step's `id` counts as done for `step_done` once the step ran (for expanded steps: once expanded).

## Cleanup pass (cast_during, notes, copies, gaps reported by 2+ decks)
Tests: `src/kernel/cleanup.test.ts`. All of it is reported as `needs` by `capabilities.ts`; the engine (`engine/support.ts`) refuses the new fields (strict mode) so nothing is skipped silently.

**cast_during semantics (user-confirmed).** "during your main phase" = a main phase of the CASTER'S OWN turn (Sphinx's Insight addendum). `Predicate cast_during.phase` now has two values: `"your_main"` (own turn only; renders "your own main phase") and `"main"` (a main phase of ANY player's turn; renders "a main phase"). The engine evaluates both (`engine/query.ts`); Sphinx's Insight uses `your_main`, so cast in an opponent's main phase it does NOT gain life (test in `engine/spells.test.ts`).

**review.notes: string[]** free-form rulings / modelling notes, never read by the validator. Draconic Visitor's rulings moved there out of `oracleOverride.source`; the card is now in `reign-of-dragons` too and identical to the `lathliss` copy.

**Copies check.** `npm run kernel:check-copies` fails when one card slug has different JSON in different deck dirs; `-- --fix` copies the best variant (fewest review.ignore, then most notes, then most decks) over the others. A vitest case enforces the same invariant.

**New schema vocabulary**
- StaticSpec `cant` + `protects: "you" | "you_and_planeswalkers"` ("can't attack you or planeswalkers you control").
- Cost atom `counters.from`: `"self"` or an ObjectFilter (remove counters from among creatures you control).
- ObjectFilter: `blocking`, `enteredThisTurn`, `attackingOpponent`, `sameNameAs` (ObjRef), `controller: "that_player" | "active_player"`.
- Steps: `vote` (`voters`, `candidates` | `voteOptions`, `tie: all_tied | controller_chooses`; ObjRef `vote_winners` = the winners), `exchange_life` (`withWho`), `regenerate`, `repeat_process` (`steps` + `repeatIf`), `create_emblem` (`emblem.abilities`, full ability records). Typed step fields `tokenTapped`, `tokenAttacking` (true | attacked_opponent | same_defender | controller_chooses), `tokenAbilities` (typed Ability[]), `noRegenerate`.
- Event `damage_prevented` (event_amount = prevented amount). Trigger `notFromZone` (also inside `alsoOn`) and `damageSource` (ObjectFilter).
- Predicates: `mana_spent {color, cmp?}` (validator counts it as the oracle symbol), `cast_with {option}` ("was cast with escape"), `name_matches {obj, among[]}` (replaces the scripted `unique_name_check`), `step_done.who` (per-player "if you do").
- Quantity: `devotion.color` may be an array (ONE count of symbols that are any of those colours; hybrid counts once), `opponents_count`, `step_result {step}` ("for each X destroyed/sacrificed this way"; for a number `choose` it is the chosen number), `step_count {step}` (times a step ran), `life_gained_this_turn {who}` (life points, not events).
- TargetSpec `anyNumber` and `maxQuantity` (Quantity). With `maxQuantity`, `count.min = 0` means "up to X", `count.min >= 1` means exactly X. `count.max` stays a placeholder of 1; the 99 hack is gone.
- ManaSpec `anyColorAmount: Quantity` ("X mana in any combination of colors").
- Modes `distinctTargets` ("each mode must target a different player"). Ability `face` (double-faced / MDFC / split cards; set on every ability of those 16 cards). ReplacementSpec `recipient` may be an ObjRef.
- Validator: `may` backed by `choose.choice:"number"`, `each` by vote, `if` by `repeatIf`, `duration` by `enteredThisTurn`/`life_gained_this_turn`.

**Draft fixes.** Athreos (one devotion count), Arcane Denial (controller picks 0-2), Woe Strider (`cast_with escape`), Martial Impetus (`attackingOpponent`), Council's Judgment (vote; ties exile all tied; every player votes incl. caster), Cache Grab (Squirrel via `step_done` on the actual put-in-hand step). Mazemind Tome / Ezuri's Predation unchanged. Workarounds replaced in ~50 cards (see git diff of data/kernel-drafts).

**Scripted marker list.** `unique_name_check` is gone (schema form `name_matches`). Still scripted: see OVERVIEW.md.

## Kernel step 2: layers + replacement pipeline (engine, additive)
- `ReplacementSpec.event` gains `would_add_counters` (counters about to be put on a permanent).
- `result.set` conventions the engine reads (all values are plain JSON): `would_enter {tapped: true, counters: {kind: n}}`; `would_create_token {count: n | {multiply: n} | {add: n}, tapped}`; `would_gain_life` / `would_lose_life` / `would_add_counters {amount: n | {multiply|add}}`; `would_deal_damage {amount, damageMultiplier: n}`; `would_die` / `would_be_put_into_zone {to: zone}`.
- `would_create_token` subject: a PlayerRef ("you": the controller) or an ObjectFilter judged on the TOKEN'S OWN definition (types/subtypes/colors/token/controller/anyOf only). `instead`/`also` steps must be `create_tokens`; `event_amount` = tokens of the matched group (`instead`) or of the whole event (`also`). A literal `tokenCount` is used as written (see open question: Academy Manufactor).
- Statics: `affects: "enchanted"` is supported (Aura attached by resolution); `"equipped"` waits for equip. `grant`/`lose` take passive keyword names; `lose: "all abilities"` removes abilities of earlier timestamps only.
- Runtime state (types.ts, not card JSON): `GameObject.attachedTo/attachedToTs/castX`, `TokenDef.abilities`, `ContinuousEffect.lose/base/addTypes/setColors`, decision kind `order_replacements`, pending ctx `replay`.

## Kernel step 3: combat, decisions inside replacement effects (engine, additive)
- Phases: `first_strike_damage` added to `PHASES` (the engine's combat steps are beginning_of_combat, declare_attackers, declare_blockers, first_strike_damage, combat_damage, end_of_combat; the legacy `combat` phase is no longer entered). Trigger `begin_step` now works for `declare_attackers`, `declare_blockers`, `end_of_combat` too.
- No new card vocabulary; the engine now RUNS existing vocabulary: statics `cant` (`attack` with `except` / `protects`, `block`, `be_blocked`), `mustAttack`, `attackTax`, `blockTax`, `evasion`; triggers `attack`, `block`, `deals_damage`, `deals_combat_damage_to_player`, `dealt_damage` (with `batch`, `minCount`, `defender`, `damageSource`, `alsoOn`); filters `attacking`, `blocking`, `attackingYou`, `attackingOpponent`; predicate `source_state: attacking`; step `extra_combat`; step `choose` with `choice: "color"` (`exclude`, `remember`); the keyword `skulk` is a passive keyword; scripted handler `roll_d20_result_is_X` (`params.sides`, result = X).
- Interpretation notes: `cant be_blocked.except` = the blockers that CAN block it; `cant attack.except` / `cant block.except` = creatures exempt; an `attackTax` / `blockTax` cost must be plain mana (`{2}`, `{W}`); several `mana.produces` specs are ALTERNATIVES (each one fixed mana symbol), the player picks when activating. Damage assignment uses the current rules (no damage assignment order): an attacker with two or more blockers divides damage freely (decision kind `assign_damage`, `Choice.assign`).
- Runtime state (types.ts, not card JSON): `GameState.combat` / `extraCombats`, `GameObject.dtHit` / `chosen`, `Choice.assign`, `PendingView.amounts`, actions `declareAttackers` / `declareBlockers`, error codes `declaration_pending`, `not_declaring`, `not_your_declaration`, `illegal_attack`, `illegal_block`, `attack_requirement`, pending ctx `combat_damage`, replay ctx `delivered`.
- Draft fix: Academy Manufactor (`squirreled-away`): each of the three `create_tokens` steps used a literal `tokenCount: 1`; they now use `{ref: "event_amount"}` (the number of tokens of the matched group), so creating two Treasures makes two Clue, two Food and two Treasure, as the card's rulings say. Draconic Visitor and Chatterfang already used `event_amount`; no other token-replacement draft had the literal.

## Kernel step 4: choose / move / search / costs / hidden information (engine, additive; no card JSON changed)
- No new schema vocabulary. The engine now RUNS existing step vocabulary: `choose` (`choice: color | mode | number`, or `from` / `fromLooked` + `count` / `upTo` / `anyNumber` / `saveAs` / `who`), `move_card_zone` (`what` = saved name | `rest_of_looked_cards` | `looked_cards` | `top_of_library` | `all` | `graveyard_of_tN` | `choose`; `who`, `filter`, `moveFrom` / `from` + `moveCount` | `all`, `position`, `ordered: any_order` / `order: random | chosen`, `shuffle`, `withCounters`, `underControlOf: owner`, `saveAs`), `search_library`, `look_top`, `reveal` (`what: top_card_of_library` or `target`), `repeat_for_each` (`over`: `each_opponent` | `each_player` | an object filter), `add_mana` (one fixed `colors` spec), `life_change.lose`, `unlessPay` on any step (mana / life costs), `grant_effect` with `filter` (+ `who`).
- Conventions the engine reads: a `choose` / `search_library` / `move_card_zone` result is saved under `saveAs` (else the step `id`, else "chosen" / "found"); later steps read it with `target: "chosen"`, `what: "<name>"` or the ref `chosen`. `saveAs: "event_object"` also sets the event object. A saved OBJECT is remembered with its timestamp: once it changed zone it is a new object and is no longer referenced (a `saveAs` on the move step re-points it). `{ref: "step_result", step}` = the number a `choose number` returned, or how many cards a `move_card_zone` / `search_library` moved / found, or how many permanents `destroy_all` destroyed (the step needs an `id`). In `search_library` / `choose`, `who` is the player who decides (and, for a search, whose library is searched). `move_card_zone.who` is the controller for a target / saved-list form going to the battlefield, and the player whose zone it is for the zone form. A search for a quality may find nothing (701.19b); a search with an empty filter must take a card.
- Costs: `sacrifice` / `discard` / `exileFrom` (graveyard, hand, exile; `what: "self"` from the battlefield) / `tapOther` / `returnToHand` with a filter are asked as `choose_cards` decisions during activation, before anything is paid; `life` takes a quantity. `discard: "self"` (cycling), `counters` from a filter, `loyalty`, `reveal`, `energy`, `untap` are still reported as unsupported. These choice costs are refused on MANA abilities (`cost:mana_ability_choice`).
- Runtime state (types.ts, not card JSON): decision kinds `choose_option`, `choose_number`, `pay_unless`; `Env.savedTs/lastChosen/looked/thatPlayer`; `StackItem.sacrificed/costLki` (ref `sacrificed`: last-known info of what was sacrificed as a cost); `GameObject.faceDown`; events `reveal` (public), `looked_at` (private), `library_searched`, `cards_chosen`, `option_chosen`, `number_chosen`; `zone_change` events carry `owner`; `Draft.costChoices`; hidden-information views in `engine/view.ts` (`viewFor`, `eventsFor`, `pendingFor`, `viewResult`).
- Bug fixes found on the way: a token moved off the battlefield no longer leaves a dangling id in the destination zone list; the filter type `permanent` matches permanent cards in a graveyard / hand / library when the filter names that zone (Deadly Brew shape).

## Kernel step 6: conditional target slots + engine long tail (additive)
- **Schema (additive):** `TargetSpec.onlyIf` (optional `Predicate`): the target slot exists only while the predicate holds when the spell is cast / the ability is put on the stack (the options chosen so far are known, so `{check: "kicked"}` works). An inactive slot is never asked or validated, its target list is empty and refs to it resolve to nothing. Tear Asunder now has `t1 onlyIf not kicked` and `t2 onlyIf kicked` (data/kernel-drafts/squirreled-away/tear-asunder.json), so an unkicked cast no longer asks for the kicked target.
- **No other vocabulary changed.** New conventions the engine reads from existing fields: `replacement.optional` (a "you may" replacement: the affected player is asked yes/no, deterministic replay; `result.set.unlessPay {life: N}` on `would_enter` = "you may pay N life, if you don't it enters tapped", asked only when affordable); `copy` with `of` / `asEnters` / `addAbility` / `exceptGrant` / `duration` / `all+filter+becomes` (layer 1 copy effect, `GameObject.copyDef`); `create_emblem` (command-zone token object, abilities get ids `emblem:<id>`); `add_mana.produces` with several specs / `anyColor` / `chosenColor` (no `restriction` / `abilitiesOf` / `duration`); `{ref: players_count | opponents_count | devotion | commander_colors}`; `stat controller_is_monarch` and `<kind>_counters` predicate stats; scripted `become_monarch` / `crew`; hybrid / Phyrexian mana symbols in costs.
- Runtime state (types.ts, not card JSON): `GameState.monarch`, `GameObject.copyDef` / `copyUntilEot`, `DurableEffect.control`, `EngineContext.db` / `Run.db` (`CardDb`, `CardInfo`), `CardDef.layout` may be "adventure", `ParsedCost.hybrid` / `phyrexian` / `symbolColors`, draft stage "crew".
- Host contract added: `CardDb` (creatureTypes / cardNames / card(name) -> printed data, faces, layout). Optional; without it "choose a creature type / card name" offers the core list + every card in the game.
