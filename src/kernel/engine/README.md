# src/kernel/engine: deterministic rules core (kernel step 1)

Pure TypeScript, no UI, no I/O, not wired into the app. `resolve(state, action, ctx) -> { state, events, pending?, error? }`.
Card definitions come from kernel-schema JSON (`data/kernel-drafts/**`) through a lookup the HOST passes in (`ctx.cards`); the engine never reads files (only `testkit.ts` does).

## State shape (`GameState`)
`players[]` (life, `library/hand/graveyard/exile/command` as ordered id lists, `manaPool`, `landsPlayed`, `colorIdentity`, `hasLost`), `objects` (id -> `GameObject`: owner, controller, zone, `timestamp`, `controlledSince`, `tapped`, `counters`, `damage`, `token`), `battlefield[]`, `stack[]` (`StackItem`: spell / activated / triggered, chosen `parts` = modes with targets, `x`, `cast` info = phase/turn/caster when cast), `turn {number, active, phase}`, `priority`, `passes`, `effects[]` (timestamped continuous effects), `turnLog` (per-turn events for `count_this_turn`, `nth`), `triggerQueue`, `pending`, `gameOver`, `rngState`/`seed`, `config`.
Object ids are `#<n>`; player ids are host-chosen strings that must not start with `#`. Everything is JSON-serializable; `resolve` clones its input and returns the ORIGINAL state object on any error.

## Actions (every action carries `player`)
`castSpell {cardId, modes?, targets?, x?, payWith?, autoPay?}` · `activateAbility {sourceId, abilityId, targets?, x?, color?, payWith?, autoPay?}` · `playLand` · `passPriority {fastForward?}` · `answerDecision {decisionId, choice}` · `advancePhase` · `declareAttackers {attackers: [{id, defender}], payWith?, autoPay?}` · `declareBlockers {blocks: [{blocker, attacker}], payWith?, autoPay?}`.
`modes/targets/x` inside an action are a shortcut: they are validated exactly like answers. `autoPay` defaults to true (tap sources greedily when the pool is short); `autoPay:false` pays from the pool only. Mana abilities (kind `mana`) resolve immediately and add to the pool; they are used through `activateAbility`.
`advancePhase` is "everyone passes with an empty stack" for the active player (adapter convenience). The real mechanism is `passPriority`: with an empty stack, all alive players passing in turn order ends the step; with a non-empty stack the top object resolves, then the active player gets priority. `fastForward` repeats that until the stack is empty or a decision is pending.
Rejections (`error.code`): `not_your_priority`, `decision_pending`, `not_your_decision`, `wrong_decision`, `no_decision`, `not_owner`, `not_in_zone`, `wrong_timing`, `land_limit`, `illegal_target`, `invalid_choice`, `cannot_pay`, `cannot_activate`, `unsupported` (+ `capability[]`), `unknown_card/object/ability`, `loop_detected`, `game_over`; combat: `declaration_pending` (something else was sent while attackers / blockers are awaited), `not_declaring` (no such declaration is open), `not_your_declaration`, `illegal_attack`, `illegal_block`, `attack_requirement` (a must-attack creature was left out).

## Decision / pending protocol
Whenever a player must choose, `resolve` returns `pending` (also stored in `state.pending`, and while it is set only `answerDecision` is accepted):
`{ id, kind, player, prompt, options[{id,label}], min, max, repeatable?, numeric?, cancellable }`.
`kind`: `choose_modes`, `choose_targets`, `choose_x` (numeric answer), `choose_cards` (discard, sacrifice, scry/surveil, cleanup), `choose_yes_no` (optional/"may" steps), `choose_color`, `order_triggers`, `assign_damage` (an attacker blocked by several creatures: answer `choice: {assign: {<recipient id>: damage}}`; `pending.amounts` = total, lethal per blocker, trample), `order_replacements` (several replacement effects apply to one event and the order changes the result; options = the effects, answer one id = the one to apply first).
The prompt is the card JSON's (`prompt`, `xPrompt`, mode/target prompts), falling back to `prompts.ts` builders. Options are computed from the CURRENT zones when the question is asked and re-validated when it is answered: a spell being cast is on the stack (never a discard candidate), `choose_cards` for a discard lists only that player's hand, targets exclude the spell itself and hexproof/shroud objects, a mode with no legal target is not offered. Answer with `choice: {ids}` | `{number}` | `{yes}`; casts can be abandoned with `{cancel:true}` (card returns to its old hand slot, nothing was paid). A bad answer returns `error` and leaves the pending decision open.
Internally a resolving ability is an `Exec` (stack of step frames + env) stored inside the pending decision, so continuing is not a replay: `answerDecision` re-enters the interpreter at the step that asked. Steps never mutate before they ask.
Order of choices when casting: modes -> targets (per chosen mode, in order) -> X -> payment (last, so cancel is free). Triggers: APNAP; a player with several triggers gets `order_triggers` (first chosen goes on the stack first, resolves last); a trigger with targets asks for them when put on the stack; a trigger with no legal target is removed (`trigger_removed`).

## What is supported
- Zones/turn: untap, upkeep, draw (first player skips on turn 1 in 2-player), main phases, combat (beginning of combat, declare attackers, declare blockers, first-strike damage, combat damage, end of combat), end step, cleanup (hand-size discard decision), turn rotation, mana pool emptying, summoning sickness (`controlledSince` vs the controller's turn start), the combat phase (below).
- Casting: sorcery vs instant/flash timing, `timing.only` predicates, `limit` per turn/game, commander from the command zone (tax), X, modes (min/max/distinct/repeatable), targets (`count` min/max, filters, spell targets), pay from pool/auto-tap, LIFO resolution, fizzle (all targets illegal), partial fizzle (legal targets still resolve), counter_spell, permanent spells enter the battlefield.
- Abilities: mana abilities (fixed colors, any color, commander identity, with simple steps such as pain), activated abilities with costs `mana`, `{T}`, sacrifice self, life, counters on self; supported on the stack with LKI (`r.s.lki`) for "its power/controller".
- Triggers: `etb`, `dies` (subject self or filter, last-known info), `cast` (subject each_player/you/opponent/filter, `nth` per turn), `begin_step` (upkeep, draw, end_step, beginning_of_combat; yours/opponents/each), `interveningIf` checked on trigger and on resolution.
- Static abilities and layers (see below), replacement effects (see below), Auras (`enchant`: the spell's target is the host, attached on resolution, SBA 704.5m when the host is gone), predefined Treasure / Food / Clue tokens (their mana / activated abilities work).
- State-based actions: 0 life, empty-library draw, lethal damage (indestructible), 0 toughness, last player standing / draw. Legend rule, planeswalker 0 loyalty, token cleanup beyond zone change: not yet.
- Steps (29): draw_cards, life_change, drain, damage_target, destroy_target, destroy_all, exile_target, bounce_target, mass_bounce, reanimate, mill, discard, tap_target, untap_target, pump_target, mass_pump, grant_effect (until end of turn: keyword grant, `lose` abilities, setBasePT, addTypes, setColors), create_tokens (Treasure/Food/Clue carry their rules; Blood/Map/Powerstone/... still unsupported), put_counters_on_self, add_counters, remove_counters, sacrifice_permanent, move_card_zone (target-based), counter_spell, shuffle, scry, surveil, connive, if_else. Plus `optional` ("may") on any step, `condition` (on_resolution/on_cast/on_trigger) with predicates: cast_during, cast_from, turn_is, phase_is, controls, life, zone_count, did_this_turn, nth_this_turn, compare, stat, matches, source_state, step_done, most_life.
- Quantities: numbers, math, X, count, stat, counters, life_total, count_this_turn, greatest, sum, event_amount, life_lost_this_way.

## Combat (`combat.ts`, flow in `resolve.ts`)
- **Steps.** beginning_of_combat -> declare_attackers -> declare_blockers -> first_strike_damage (only when a first / double striker is in combat) -> combat_damage -> end_of_combat, each with N-player priority. `state.combat` = `{attackers: [{id, ts, defender, blockers[], blocked}], dealtFirst[], expect}`; `extraCombats` counts additional combat phases (step `extra_combat`).
- **Declarations are turn-based actions, not priority.** On entering declare_attackers the active player gets `combat.expect = {kind: "attackers", player}` and `priority` is null: only `declareAttackers` is accepted (everything else: `declaration_pending`; `advancePhase` by that player means "no attack"). If no creature could attack, or none is declared, blockers and damage are skipped (508.8). In declare_blockers every attacked player (or planeswalker / battle controller) with a legal blocker is listed in `expect.players` and declares `declareBlockers` for their own creatures, in any order; players with nothing to declare are not asked.
- **Legality reads effective characteristics.** Attack: untapped creature you control, no defender, not summoning sick (haste exempt; "controlled continuously since your most recent turn began"), no `cant attack` static (with `except` = creatures exempt, `protects: you | you_and_planeswalkers` = only attacks aimed at the source's controller / their planeswalkers), `mustAttack` creatures that could attack must be included (`attack_requirement`), defender = an opponent or an opponent's planeswalker / battle (by id). Block: untapped, no `cant block`, flying / reach, intimidate, fear, skulk, unblockable, `cant be_blocked` (`except` = blockers allowed), static `evasion` (cantBeBlockedBy / unlessDefenderControls), menace (two or more blockers), one attacker per blocker.
- **Taxes** (`attackTax`, `blockTax`, plain mana costs) are paid when declaring: pool first, then tapping sources (`payWith` / `autoPay:false` as for casting); not payable = `cannot_pay` and nothing happened. Declaring is the decision (attack with fewer creatures to pay less).
- **Damage.** Simultaneous per step through `dealDamage` (the replacement pipeline: prevention, redirection...), double strike in both steps, first strikers do not deal again, lifelink on damage actually dealt, deathtouch (`dtHit`, destroyed by SBA unless indestructible), damage to planeswalkers (loyalty) and battles (defense), SBA for 0 loyalty / defense. Trample: lethal accounts for damage already marked and deathtouch (1); with one blocker the rest goes to the defender automatically. A blocked creature without trample whose blockers are gone deals nothing. Damage assignment follows the CURRENT rules (no damage assignment order): an attacker with two or more blockers asks its controller to divide the damage freely (`assign_damage`); with trample the defender may only get damage once every blocker has lethal.
- **Triggers.** `attack` (subject self / filter / enchanted / equipped / player subjects with `whose`, `defender`, `batch` + `minCount`), `block`, `deals_damage`, `deals_combat_damage_to_player` (`batch`), `dealt_damage` (`damageSource`), and `alsoOn` alternatives (attacks or blocks). Context: for attack triggers `event_object` = the attacker and "that player" = the defending player. Triggers scan the events BEFORE state-based actions, so a creature that deals damage and dies at the same time still triggers. Filters `attacking`, `blocking`, `attackingYou`, `attackingOpponent` and the predicate `source_state: attacking` read the combat state.
- Scripted marker `roll_d20_result_is_X` (Ancient Copper Dragon family): rolls with the seeded RNG at resolution, emits `die_rolled`, and the result is X for the steps.

## Kernel step 4 (choose / move / search / costs / hidden information)
- **choose** (`choose.ts`): cards or permanents from a candidate list computed from the CURRENT zones (`from` filter, or `fromLooked`: the cards a `look_top` looked at), `count` / `upTo` / `anyNumber`, also colors, named modes and numbers. The answer is saved (`saveAs` / step id / "chosen"). `who` is the chooser. Forced choices (as many candidates as the count) are made without asking; "up to" and searches allow zero.
- **Saved references and new objects** (`saved.ts`): saved objects carry the timestamp they had when saved; a card that changed zone since is a new object (400.7) and is silently no longer referenced; `saveAs` on a move step re-points the name. `{ref: "step_result"}` reads numeric results.
- **move_card_zone** (`moves.ts`): any zone to any zone through `moveObject` (dies / leaves / enters / would-be-put-into-zone replacements, ETB triggers, enters tapped / with counters, tokens cease to exist). `what` forms, `who`, `filter`, library `position` top / bottom, order: `ordered: any_order` (asks the controller) / random (seeded RNG), `shuffle`. Not done: "Nth from the top" (no such vocabulary), a count from a non-library zone, face-down, link-exile.
- **search_library / look_top / reveal** (`library.ts`): the searching player (`who`) decides, sees only matching cards, may fail to find, shuffle uses the seeded RNG; destinations hand / battlefield (tapped) / library top-bottom / graveyard. `reveal: true` emits a public `reveal` event; otherwise the search is private. `look_top` emits the private `looked_at` and remembers the cards for `fromLooked` / `rest_of_looked_cards`.
- **repeat_for_each** (`repeat.ts`): a snapshot of `each_opponent` / `each_player` / a filter; each iteration sets `iterated` (objects) or "that player".
- **Costs** (`costs.ts`): see SCHEMA_CHANGELOG. The decision is asked after modes / targets / X and BEFORE payment, so cancelling is free; auto-chosen when there is exactly the needed number of candidates; tapping others ignores summoning sickness; a sacrificed permanent's last-known info is readable by the ability (ref `sacrificed`).
- **unlessPay** (`unlesspay.ts`): any step "unless <payer> pays <mana / life>"; a payer who cannot pay is not asked; yes pays (auto-tapping) and skips the step, no runs it.
- **Hidden information** (`view.ts`): the server keeps the full state. `viewFor(state, player)`: own hand listed, others' hands and every library as counts, face-down cards of others anonymous, seed / rngState / decision continuations (`ctx`, replay base state) removed, the turn log's draw ids removed. `eventsFor(state, player, events)`: a draw by someone else has no card, a hand/library -> hand/library move of someone else's card has no id / name (`hidden: true`), `looked_at` only for the looker; `reveal` is public. `pendingFor`: another player's decision keeps kind / prompt / bounds and has NO options (`hidden: true`, `optionCount`). `viewResult(res, player)` bundles them. The adapter sends `viewResult(res, p)` to each seat instead of the raw result.

## What is NOT supported (returns `error.code = "unsupported"` with `capability[]`, never skipped)
Not done in step 4: `cast_option` of every kind (kicker, flashback, escape, additional casting costs, alternative costs, "cast from graveyard"), `predicate:paid_additional_cost`, `add_mana` with several specs / restrictions / variable amount, player-scoped `grant_effect` (`replacement`, `who` without filter), loyalty / cycling (`discard: self`) / counters-from-filter costs, `create_delayed_trigger` (so Arcane Denial and Portent still need it; their `choose number` half works), `choose` of creature type / card type / card name / player, `reveal` of a filtered hand card, search with `totalManaValueAtMost` / `distinctNames`, `repeat_for_each` with a count chosen by the player. Combat leftovers (must-block / "blocks each combat if able", can-block-additional, attacking-creature entry effects `tokenAttacking`, removing a creature from combat, "becomes blocked" triggers, commander damage, banding / protection details, forced attack targets), search_library, choose, look_top, reveal, copy, equip / attach step (`affects: "equipped"`), gain_control, permission_to_play, create_delayed_trigger, repeat_for_each, add_mana step, unless_pay, cast options (kicker/flashback/cycling/...), `costReduction` other than a spell's own affinity, cost reduction on abilities, loyalty as a cost, hybrid/phyrexian mana, planeswalkers, triggers other than etb/dies/cast/begin_step, per-opponent targets, durations other than end of turn, optional ("you may") replacement effects, replacement shields from activated abilities (Spore Frog), `would_become_tapped`, `would_enter` choices other than a color / a life payment (Snarls: reveal, copy), static effects on players ("you have hexproof", "can't lose") and `grantAbility`, static `cant` other than attack/block, layer 1-3 (copy, control, text).
Strict by default (`config.onUnsupported = "error"`; the live-game mode is described in "Unsupported things mid-game: continue mode" below): casting/playing a card refuses if ANY of its abilities is unsupported (so a Tome with an unsupported state trigger cannot enter play). `config.lenient: true` lets it in and emits an `unsupported_ignored` event per ability. Activating an ability only checks that ability. `debugPlaceCard` (host/tests) bypasses all of this and is not an action.
The loop guard: more than `config.maxEventsPerPass` (5000) events inside one `resolve` call (e.g. `fastForward` over a mandatory trigger loop) returns `error.code = "loop_detected"` and a state with `gameOver = {draw:true}` (rule 722.1). Optional loops (player names an iteration count) are not modelled yet.

## Unsupported things mid-game: continue mode (`config.onUnsupported`, unresolved.ts)
POLICY (user, 2026-11-22): when the kernel meets a card / ability it cannot resolve in a live game it must NOT crash, refuse the action or end the game. It reports exactly what it could not do and keeps playing.

Two modes, chosen per game in `newGame({ config: { onUnsupported } })` (`state.config.onUnsupported`):
- `"error"` (default): everything described in the section above. Casting / playing / activating something unsupported is refused with `error.code = "unsupported"` and `capability[]`. Tests, the observer's strict classification and readiness gates use this.
- `"continue"` (live-game mode): nothing is refused. Each unsupported thing emits ONE `unresolved` event and only that step / clause is skipped.

The `unresolved` event: `{ type, card, source?, zone?, ability?, abilityKind, clause, capability, capabilities[], effect, message, turn, phase, player }`. `card` names the card (or token), `clause` is the ability text from the card data, `capability` the first missing capability (`step:copy`, `cost:unsupported`, `trigger:nth`, ...; all of them in `capabilities`), `effect` is what happened instead and `message` is a ready log line ("Swan Song: step copy not supported ("..."); that part was skipped"). Same state + action + seed gives the same events (replays included).

| What is unsupported | What happens (`effect`) |
|---|---|
| a step (unknown kind, field, duration, reference, predicate / condition, or something that only fails while running, e.g. "opponent" in a 3-player game) | `skipped`: that step only; the steps after it still run, so the rest of the card resolves. Judged when the ability resolves, deduped per card + ability + capability within one action |
| a cost of an activated / mana ability, or any other frame part of it (targets, timing, zone, keyword, scripted marker, declined) | `not_performed`: never silently free. Nothing is paid or tapped, nothing goes on the stack, the player keeps priority (the action succeeds with just the event) |
| a cast option (kicker, alternative cost, flashback, overload ...) | `not_performed`: the option is not offered, the normal way to cast stays available; reported when the card is cast |
| the spell ability of a spell (targets / frame unsupported, declined) | `skipped`: the spell is cast and goes to its zone, its effect is skipped; reported when cast |
| a trigger the engine cannot detect / evaluate, a static ability the layers cannot apply, a replacement effect, a keyword ability, a scripted marker on those | `ignored`: never fires / applies; reported ONCE per object (`state.unresolvedSeen`), the first time the effects index sees it on the battlefield (right when it enters), never on later state passes |
| unsupported ability of a token / emblem a step creates | the token is still created; the ability is reported like any permanent's |
| anything else that still throws `Unsupported` inside an action (last resort in `resolve`) | `not_performed`: the action changes nothing, one event says why. The caller can retry something else |

Plumbing: `core.ts` `printedAbilities()` leaves out blocked abilities (frame unsupported) in continue mode, so layers / replacements / trigger scanning never see them; `continueHooks` (late-bound, set by unresolved.ts) avoids an import cycle. `support.ts` splits an ability's needs into frame (`abilityFrameNeeds`) and per-step (`stepNeedsShallow`). `view.ts`: `unresolved` events are public; only when the card sat in another player's hand / library does `eventsFor` replace it with a nameless `{ hidden: true, message: "A card could not be fully resolved." }`; `viewFor` never exposes `unresolvedSeen`. The older `config.lenient` (strict-mode escape hatch, `unsupported_ignored` events) is unchanged and ignored when `onUnsupported = "continue"`.

Host side (the kernel does no I/O): `src/kernel/unresolvedBridge.ts` turns the (full, unredacted) events into sink records of `src/lib/unresolvedLog.ts` (`engine: "kernel"`, card, clause, capability, seat, turn, phase):
```ts
const bridge = new UnresolvedBridge({ gameId, decks, seatKindOf }, (rec) => appendUnresolvedRecord(rec)); // server: data/observer/live-unresolved.jsonl
const res = resolve(state, action, ctx);
bridge.push(res.events);          // once per game + card + clause + capability
```
`npm run kernel:observe -- --continue` runs the observer's kernel in continue mode and writes `<out>/kernel-unresolved.jsonl`; `npm run unresolved:report -- <out dir>` lists kernel and legacy occurrences together (engine and capability columns).

## Static abilities and layers (`layers.ts`)
`chars(r, id)` is the ONLY place the rest of the engine reads power/toughness/types/colors/keywords/abilities. It starts from the copiable values (card JSON or token definition) and applies, in layer order, every static ability of a permanent on the battlefield (plus statics whose ability `zone` is graveyard/command) and every timestamped temporary effect (`state.effects`: "until end of turn" grants):
- 4 types (`addTypes`, `setTypes`; a basic land type adds its intrinsic mana ability), 5 colors (`setColors`), 6 abilities (`grant`, `lose`), 7a characteristic-defining P/T (`setBasePT` on "self" with a computed quantity), 7b `setBasePT` (later timestamp wins), 7c `pt` effects then +1/+1 / -1/-1 counters (regardless of timestamp). Timestamp = the source object's `timestamp` (refreshed when it changes zone), or the effect's own.
- "Loses all abilities" (`lose: "all abilities"`) removes the abilities collected by EARLIER timestamps only; grants with a later timestamp are kept; when the Aura leaves, everything is computed again from scratch (nothing is stored), so the object is restored.
- `affects`: `"self"`, `"enchanted"` (Aura host: `attachedTo`), or an object filter evaluated against the object's PARTIAL characteristics at the moment the layer applies (so "creatures you control" sees something a lower layer turned into a creature). `while` is any supported predicate. A layer-7 effect is dropped when its source has lost the static ability; layer 4-6 effects keep applying (613.6). Statics are read from the printed ability list, so a stripped permanent's own statics stop in layer 7 but its type/color changes survive (approximation of dependencies, 613.8).
- Effective abilities: `abilitiesOf(r, o)` returns what layer 6 leaves on the battlefield; triggers, activated/mana abilities and the replacement collector read it, so a stripped permanent has no triggers and no abilities. Elsewhere the printed list.
- Not through chars: restrictions (`restrictionsOf`, `canAttack`, `canBlock`, `mustAttack`), `landDrops` (`extraLandDrops`), `spellCostDelta` (`costMod` statics of permanents + a spell's own affinity-style `costReduction`; the delta is added to the generic part of the cost, never below 0).
- No cache: chars is recomputed per call (cheap fast path when nothing in play is static or temporary). The static/replacement source list is cached per `resolve` call and dropped by every zone change.

## Replacement effects (`replacements.ts`)
Every replaceable event is a plain object passed through `applyReplacements(r, event)` BEFORE it happens, at the choke point: `moveObject` (`enter` for the battlefield, `zone` for everything else incl. would die / would be put into a zone), `drawCards` (`draw`, once per card), `changeLife` (`gain_life` / `lose_life`, damage to a player also passes the latter), `dealDamage` (`damage`, with a `combat` flag), discard (`discard`), counters being put on (`counters`), the create_tokens step (`tokens`: one event for the whole creation, as groups of identical tokens).
1. Collect applicable effects: replacement abilities of permanents in play (effective abilities) + the entering/moving object's own; an effect that already applied to this event, or whose steps are running now, is excluded (each effect applies at most once). Token subjects are judged on the token's OWN definition, before any static (Draconic Visitor vs Mycosynth Lattice).
2. Self-replacement effects first. Otherwise, if several apply and the orders can give different results, the AFFECTED player (token creator / drawer / life gainer / damaged player or permanent's controller / mover's owner) answers an `order_replacements` decision (prompt text built here; the effect's own `prompt.title` is used as the option label when present). Pure effects (modify / prevent / token groups / enters-with-counters) are simulated in every order: if all orders give the same result no question is asked (two enters-tapped effects).
3. Apply it: `modify` (`set` conventions in SCHEMA_CHANGELOG), `prevent`, `instead` (token groups are rewritten; other kinds run the effect's steps now with `event_object` / `event_amount`, and the original event is cancelled), `also` (token groups added / counters added to the entering permanent / steps run after the event). Repeat.
**Replay protocol.** The ordering question can arise deep inside any choke point, where the resumable-step mechanism cannot reach. So `NeedOrder` aborts the whole `resolve` call and the pending decision stores `{base state, action, answers so far}` (PendingCtx `replay`); answering re-runs the same action from `base` with one more recorded answer. The engine is deterministic (seeded RNG in the state), so the re-run reaches the same question. Consequences: the returned state while the question is open is the OLD state plus the pending decision (nothing has happened yet), but the events emitted before the question ARE delivered with it (`events` of the call that returned the question), and the pending context remembers how many were delivered (`delivered`): the replay re-emits the same prefix and returns only what is new, so no event is lost or duplicated and `seq` stays one continuous sequence. Answers are stored as `Choice` objects, one per question, in order; decision ids stay unique across the questions of one action. A replacement effect's own steps may ask the player (`runInline` throws `NeedAsk`): shock lands ("you may pay 2 life, else enters tapped": `choose_yes_no`) and Thriving lands ("choose a color": `choose_color`, the answer is remembered on the permanent as `chosen.color`). For `would_enter` the steps run BEFORE the permanent moves (`replacements.applyEnterSteps`): `tap_target` on it = "enters tapped", `add_counters` on it = "enters with counters" (both change the pending event, `Run.entering`).
Supported: `would_enter` (modify tapped/counters, also add_counters incl. X), `would_create_token` (instead/also create_tokens, modify count/tapped, prevent), `would_draw`, `would_gain_life`, `would_lose_life`, `would_deal_damage` (prevent, modify amount / damageMultiplier, instead/also steps, damageType, damageSource, recipient), `would_die` / `would_be_put_into_zone` (instead/also steps, modify `to`), `would_discard`, `would_add_counters`. `condition` predicates are honoured.

## Kernel step 5 (cast options, durable effects, attach, copy, more triggers, faces, more choose)

- **Casting is an option stage** (`advanceDraft`): face (only when several faces are castable) -> HOW (normal / flashback / escape / alternative cost / cast-from-zone / a `perm:` permission; one `choose_cast_option` question, skipped when only one way exists) -> optional extras (kicker, gift, optional additional costs: one multi-select `choose_cast_option`, min 0) -> modes -> targets -> X -> costs that need a choice -> payment. Mandatory additional costs and escalate are added automatically. Total mana = base (or the replacing option's) + extras + escalate per extra mode + commander tax + `costMod`s; non-mana costs of the options (life X, sacrifice, discard, tap, exile) use the normal cost choices. `castSpell` shortcuts: `option` ("normal" or an option id), `extras`, `face` (validated like answers). Loyalty: `cost.loyalty` (also -X), one loyalty ability per planeswalker per turn at sorcery speed, starting loyalty from `CardDef.loyalty`.

Permissions (`permission_to_play`: refs `exiled`/`chosen`/`tN`/`event_object`, durations end of turn / end of your next turn / your next end step, `withoutPaying`, `allow` land/spell; used up by the cast or land play; invalid once the card changed zone), replacement shields (`grant_effect` with `replacement`, read by the replacement pipeline), player flags (`no maximum hand size`). `create_delayed_trigger`: `at: begin_step` (next occurrence after creation; whose yours/each) or `dies` of saved objects this turn; the trigger carries the creating ability's targets; several due triggers are ordered like any others.

## Kernel step 7 (the tail: per-unit mana, counters decisions, commander, linked exile, miracle / evoke / improvise, batch triggers)

- **Mana is per unit** (`manapool.ts`).
